    Status & feedback

    Sinalizar estado, sucesso, erro, atividade. Spinners, skeletons, alertas, KPIs.

    O que é esta categoria

    Componentes que comunicam estado ao usuário — o que aconteceu, o que está acontecendo e o que não tem ali. Agrupam-se por intenção:

    • Mensagens (sucesso/erro/aviso): Alert (inline), Banner (topo da página), Toast (transiente) — três escopos do mesmo conceito.
    • Rótulos de status: Badge (status fixo), Tag (chip removível), Stat (KPI).
    • Atividade/carregamento: Spinner, Progress, Skeleton, NProgressBar (barra fixa no topo).
    • Estados vazios/erro de tela: EmptyState, ErrorState.

    Quando usar: sempre que o usuário precisar saber o resultado de uma ação ou o estado de um dado. A regra de ouro: nunca deixe uma ação assíncrona sem feedback — mostre Spinner/Skeleton durante, Toast/Alert ao terminar.

    Alert vs Banner vs Toast — escolha pelo escopo

    Alert é inline e fica até o usuário resolver o contexto. Banner é persistente no topo e vale para a página/app inteiro. Toast é transiente e some sozinho. Use Toast para confirmações rápidas, Alert para erros ligados a um campo/seção, Banner para avisos globais (manutenção, expiração).

    Alert

    Seção feedback-extra da gallery — rode localmente para interagir.

    Quando usar: mensagem ligada a um contexto específico da tela (erro de formulário, resultado de uma operação numa seção). Fica visível até a condição mudar.

    Banner inline. Diferente de Banner (top-of-page) e Toast (transient).

    import { useState } from "react";
import { Alert } from "tempest-react-sdk";
import { AlertCircle } from "lucide-react";

export function Avisos() {
    const [open, setOpen] = useState(true);

    return (
        <>
            <Alert variant="success" appearance="soft" title="Salvo">
                Suas alterações foram aplicadas com sucesso.
            </Alert>

            {open && (
                <Alert
                    variant="danger"
                    appearance="outline"
                    icon={<AlertCircle size={16} />}
                    onClose={() => setOpen(false)}
                >
                    Falha ao processar pagamento.
                </Alert>
            )}
        </>
    );
}
    Prop Tipo Default
    variant "neutral" \| "info" \| "success" \| "warning" \| "danger" "info"
    appearance "soft" \| "solid" \| "outline" "soft"
    title ReactNode —
    icon ReactNode —
    description ReactNode —
    onClose () => void (renderiza o botão de fechar) —
    closeLabel string —

    A11y: role="status" para info/success, role="alert" para warning/danger.

    Banner

    Seção data-display da gallery — rode localmente para interagir.

    Persistente, top-of-page. Use para environment indicators, manutenção, expiração.

    import { useState } from "react";
import { Banner, Button } from "tempest-react-sdk";

export function AvisoDeAssinatura() {
    const [open, setOpen] = useState(true);
    if (!open) return null;

    return (
        <Banner
            variant="warning"
            dismissible
            onDismiss={() => setOpen(false)}
            action={<Button size="sm">Renovar</Button>}
        >
            Sua assinatura expira em 3 dias.
        </Banner>
    );
}

    Stat

    Quando usar: destacar uma métrica única com variação (receita, sessões, NPS) em dashboards. Para vários KPIs lado a lado, combine com Grid.

    KPI card para dashboards.

    import { Stat } from "tempest-react-sdk";
import { TrendingUp } from "lucide-react";

export function Metricas() {
    return (
        <>
            <Stat
                label="Receita"
                value="R$ 12.345"
                delta="+12,4%"
                hint="vs. mês anterior"
                icon={<TrendingUp size={16} />}
            />
            <Stat label="Sessões" value="1.2k" delta="-3%" hint="últimos 7 dias" />
            <Stat label="NPS" value="78" delta="0" trend="flat" />
        </>
    );
}
    Prop Tipo Default
    label ReactNode —
    value ReactNode —
    delta ReactNode —
    trend "up" \| "down" \| "flat" inferido por +/- em delta string
    higherIsBetter boolean true
    hint ReactNode —
    icon ReactNode —

    Polaridade: quando subir é ruim

    A cor do delta diz bom ou ruim, não "subiu" ou "desceu". Por padrão, alta é verde e queda é vermelha. Em métrica onde crescer é o problema — taxa de faltas, churn, tempo de resposta, chamados abertos — passe higherIsBetter={false}: a alta fica vermelha e a queda, verde. A direção não muda; trend e o texto do delta continuam dizendo para onde o número foi.

    import { Stat } from "tempest-react-sdk";

export function TaxaDeFaltas() {
    return (
        <Stat
            label="Faltas"
            value="7,5%"
            delta="+1,2 p.p."
            higherIsBetter={false}
            hint="vs. semana passada"
        />
    );
}

    O delta expõe data-trend (up/down/flat) e data-tone (positive/negative/neutral), para teste ou estilo do app sem depender de classe com hash.

    Progress

    Seção advanced da gallery — rode localmente para interagir.

    Barra de progresso.

export function Barras({ uploadProgress }: { uploadProgress: number }) {
    return (
        <>
            <Progress value={uploadProgress} max={100} variant="primary" />
            <Progress value={100} variant="success" />
            <Progress indeterminate variant="primary" />
        </>
    );
}
    Prop Tipo Default
    value number —
    max number 100
    variant "primary" \| "success" \| "danger" "primary"
    indeterminate boolean false

    NProgress

    Quando usar: barra de carregamento fixa no topo da página para transições que não têm uma posição exata — navegação de rotas, requests em background. Para progresso determinístico de um upload, prefira Progress.

    Controlador imperativo (nprogress) + a barra visual (<NProgressBar>). Monte a barra uma vez perto da raiz do app e dirija o controlador de qualquer lugar (transições de rota, interceptors de fetch).

    import { Button, NProgressBar, nprogress } from "tempest-react-sdk";

async function loadPage(): Promise<void> {
    nprogress.start();
    try {
        await fetch("/api/data");
    } finally {
        nprogress.done();
    }
}

export function Raiz() {
    return (
        <>
            <NProgressBar color="var(--tempest-primary)" height={3} />
            <Button onClick={loadPage}>Carregar</Button>
        </>
    );
}
    nprogress Assinatura O que faz
    start () => void Mostra a barra e começa a "trickle" até ~0.9.
    done () => void Completa em 1 e esconde a barra logo depois.
    set (n: number) => void Define o progresso explicitamente (clamp 0..1).
    inc (amount?: number) => void Incrementa o progresso por amount.
    Prop (NProgressBar) Tipo Default
    color string var(--tempest-primary)
    height number 3
    className string —

    Ótimo com navegação de rotas

    Chame nprogress.start() ao iniciar a transição e nprogress.done() quando a rota montar. O nprogress é um singleton de módulo — não precisa de provider nem de props drilling.

    A11y: a barra usa role="progressbar" com aria-valuenow refletindo o percentual.

    Spinner

    Loader genérico.

    import { Spinner } from "tempest-react-sdk";

export function Carregando() {
    return (
        <>
            <Spinner />
            <Spinner size="lg" />
            <Spinner size="lg" caption="Carregando…" />
            <Spinner overlay caption="Carregando…" />
        </>
    );
}
    Prop Tipo Default Descrição
    size "xs" \| "sm" \| "md" \| "lg" \| "xl" "md" Tamanho do indicador.
    label string "Carregando" Rótulo acessível (lido por leitores de tela).
    caption ReactNode — Texto visível abaixo do spinner.
    overlay boolean false Centraliza num container de área cheia (position: absolute).

    Back-compat

    <Spinner /> sem caption/overlay continua um único <span role="status"> — nada muda no uso antigo.

    overlay posiciona pelo ancestral posicionado mais próximo

    overlay aplica position: absolute; inset: 0, então ele cobre o primeiro ancestral com position diferente de static. Se ninguém acima tiver posição, o spinner escapa para o container posicionado mais acima — na prática, a página inteira. Dê position: relative ao bloco que deve ficar coberto.

    Skeleton

    Quando usar: carregamento de conteúdo cuja forma já é conhecida (cards, linhas de tabela, avatar). Reduz o salto de layout. Para carregamento sem forma definida (um botão processando), use Spinner.

    Placeholder com shimmer enquanto data carrega.

    Skeleton imita o layout final

    Faça o skeleton ter as mesmas dimensões/proporções do conteúdo real — é isso que elimina o layout shift quando os dados chegam. Skeletons genéricos demais (um bloco só) confundem mais do que ajudam.

    import { Skeleton, Stack } from "tempest-react-sdk";

export function Esqueleto({ loading }: { loading: boolean }) {
    if (loading) {
        return (
            <Stack gap={2}>
                <Skeleton variant="text" width="60%" />
                <Skeleton variant="text" width="40%" />
                <Skeleton variant="rect" height={120} />
                <Skeleton variant="circle" width={40} height={40} />
            </Stack>
        );
    }
    return <p>Conteúdo carregado</p>;
}
    Prop Tipo Default
    variant "rect" \| "text" \| "circle" "rect"
    width number \| string "100%"
    height number \| string —

    O esqueleto tem que ter a forma do conteúdo real

    O ganho do Skeleton não é a animação, é a reserva de espaço: se as linhas fantasma têm largura e altura próximas do que vai entrar ali, o texto não pula quando os dados chegam. Um bloco genérico de 200px que vira um card de 340px troca o spinner por um salto de layout — que é o problema que o esqueleto existia para resolver.

    RefreshIndicator

    Seção material da gallery — rode localmente para interagir.

    Quando usar: dar ao usuário um gesto de pull-to-refresh em listas/telas roláveis no mobile (touch) — feeds, caixas de entrada, dashboards. Envolve o conteúdo rolável e dispara onRefresh quando o usuário puxa além do limite e solta.

    É um gesto de toque — não há equivalente com mouse. O Spinner do SDK aparece enquanto puxa e durante a atualização.

    import { RefreshIndicator } from "tempest-react-sdk";

interface FeedItem {
    id: string;
    title: string;
}

export function Feed({ items, refetch }: { items: FeedItem[]; refetch: () => Promise<void> }) {
    return (
        <RefreshIndicator onRefresh={refetch}>
            <ul>
                {items.map((item) => (
                    <li key={item.id}>{item.title}</li>
                ))}
            </ul>
        </RefreshIndicator>
    );
}
    Prop Tipo Default
    onRefresh () => void \| Promise<void> —
    children ReactNode (conteúdo rolável) —
    threshold number (px até disparar) 80
    disabled boolean false

    Gesto só de toque

    O RefreshIndicator escuta arrastos de toque que começam com o container no topo do scroll — não responde ao mouse. Em desktop, ofereça um botão de "Atualizar" explícito como alternativa.

    Toast

    Quando usar: confirmação transiente de uma ação que já terminou ("Salvo", "Item removido") — não exige atenção e some sozinho. Para erros que o usuário precisa resolver, prefira Alert/Banner (que ficam).

    Notificações transientes. Setup via ToastProvider + uso via useToast().

    Toast não é para erros críticos

    Toasts somem em poucos segundos — se o usuário precisar agir sobre a mensagem (corrigir um campo, tentar de novo), ela tem que persistir. Use Toast só para feedback descartável; erros acionáveis vão em Alert/ErrorState.

    import { ToastProvider, useToast } from "tempest-react-sdk";

function Salvar() {
    const toast = useToast();

    return (
        <button
            onClick={() => {
                toast.success("Salvo");
                toast.error("Falha ao processar pagamento.", { duration: 8000 });
                toast.show({
                    title: "Sincronização",
                    description: "Em andamento…",
                    variant: "info",
                });
            }}
        >
            Salvar
        </button>
    );
}

export function App() {
    return (
        <ToastProvider position="top-right" defaultDuration={4000}>
            <Salvar />
        </ToastProvider>
    );
}
    ToastApi Assinatura
    show (options: ToastOptions) => string (returns id)
    success (description, options?) => string
    error (description, options?) => string
    warning (description, options?) => string
    info (description, options?) => string
    dismiss (id: string) => void

    ToastProvider.position: "top-right" (default), "top-left", "top-center", "bottom-right", "bottom-left", "bottom-center".

    Safe-area aware.

    Ícone e alinhamento

    ToastOptions.icon recebe qualquer ReactNode — normalmente um asset do app — e o renderiza numa coluna própria à esquerda do texto. <img> e <svg> em qualquer nível dentro dela ficam limitados a 32px, sem distorcer. Nó que não renderiza nada (null, false, [], fragment vazio) conta como sem ícone.

    import { ToastProvider, useToast } from "tempest-react-sdk";

function Conquista() {
    const toast = useToast();

    return (
        <button
            onClick={() =>
                toast.show({
                    icon: <img src={"/assets/invict.svg"} alt="" />,
                    title: "Título Invicto desbloqueado!",
                    variant: "success",
                    duration: 4000,
                    align: "center",
                })
            }
        >
            Desbloquear
        </button>
    );
}

export function App() {
    return (
        <ToastProvider>
            <Conquista />
        </ToastProvider>
    );
}
    Opção Tipo Default O que faz
    icon ReactNode — Slot à esquerda do texto, para ícone. inert; decorativo (aria-hidden) se não houver iconLabel.
    iconLabel string — Nome acessível do ícone: o slot vira role="img" e é anunciado com o toast.
    align "start" \| "center" "start" Alinhamento do título e da descrição.

    O ícone é decorativo por padrão porque quase sempre repete o título ("Título Invicto desbloqueado!" ao lado da medalha). Sem isso, uma imagem sem rótulo dentro da região aria-live seria lida como "imagem" ou pelo nome do arquivo. Quando o ícone carrega informação que o texto não tem, passe iconLabel — não é preciso mexer no alt do asset.

    O slot é para ícone, não para controle: o wrapper é inert, então um botão ou link colocado ali não recebe foco nem clique. Ação sobre a notificação fica fora do toast — se o usuário precisa agir, use Alert.

    Por que o texto não é centralizado por padrão

    O toast é lido como uma frase ao lado do botão de fechar, e quase sempre empilhado com outros. Alinhado à esquerda, o texto divide a mesma borda com o ícone e com os toasts vizinhos, e uma descrição de duas linhas continua escaneável — centralizada, cada linha começa num ponto diferente. align: "center" fica para o toast curto e comemorativo, de uma linha, como o do exemplo.

    variant, duration e a fila não mudam com o ícone: a borda colorida continua indicando a variante, e o toast sem ícone mantém exatamente o layout anterior.

    useToast só existe sob um <ToastProvider>

    Fora dele o hook lança useToast must be used inside a <ToastProvider>. O provider vai na raiz do app, acima do router — se ele estiver dentro de uma rota, qualquer toast disparado de fora dela derruba a tela em vez de aparecer.

    EmptyState

    Seção table da gallery — rode localmente para interagir.

    Quando usar: uma lista/coleção retornou zero itens com sucesso (sem pedidos ainda, busca sem resultados). Sempre ofereça uma ação de saída (criar o primeiro item, limpar filtros). Não confunda com erro — para falha use ErrorState.

    "Nada por aqui" centralizado.

    import { Button, EmptyState } from "tempest-react-sdk";
import { Inbox, Plus } from "lucide-react";

export function SemPedidos() {
    return (
        <EmptyState
            icon={<Inbox size={32} />}
            title="Nenhum pedido"
            description="Quando seus clientes fizerem pedidos, eles aparecem aqui."
            action={<Button leftIcon={<Plus size={16} />}>Novo pedido</Button>}
        />
    );
}

    Estado vazio não é estado de erro

    EmptyState é para "a consulta funcionou e não há nada" — a ação sugerida cria o primeiro registro. ErrorState é para "a consulta falhou", e a ação é tentar de novo. Trocar um pelo outro faz o usuário criar um pedido duplicado quando o que caiu foi a rede.

    ErrorState

    Quando usar: uma operação falhou (request com erro, exceção) e o usuário pode tentar de novo. Diferente de EmptyState, que representa sucesso sem dados.

    Falha com botão de retry.

    import { ErrorState } from "tempest-react-sdk";

export function FalhaAoCarregar({
    error,
    refetch,
}: {
    error: unknown;
    refetch: () => void;
}) {
    return (
        <ErrorState
            title="Não foi possível carregar"
            description={String(error)}
            onRetry={refetch}
        />
    );
}

    Sem title, description ou retryLabel, os textos padrão vêm do i18n (tempest.errorState.*): em inglês com locale en, em pt-BR sem provider. description={null} some com a descrição.

    OfflineIndicator

    Quando usar: avisar que o app está offline e confirmar quando a conexão volta. Guiado por useOnline — não renderiza nada online, então monte na raiz sem if.

    import { OfflineIndicator } from "tempest-react-sdk";

export function Raiz() {
    return <OfflineIndicator position="top" />;
}

    position: "top" | "bottom" (default). Passe children pra substituir o corpo, ou onlineFlashMs={0} pra não piscar a confirmação. Veja PWA & Offline-First.

    SyncStatusBadge

    Seção pwa da gallery — rode localmente para interagir.

    Quando usar: mostrar o estado do motor offline (sincronizado / sincronizando / pendente / offline / erro). Dois modos: passe sync pra conectar direto no motor (zero fiação), ou passe tone explícito (apresentacional, testável sem IndexedDB).

    import { SyncStatusBadge, useSyncStatus, type OfflineSync } from "tempest-react-sdk";

interface Nota {
    id: string;
    body: string;
}

export function Status({ notesSync }: { notesSync: OfflineSync<Nota> }) {
    const { tone, pending } = useSyncStatus(notesSync);

    return (
        <>
            <SyncStatusBadge sync={notesSync} />
            <SyncStatusBadge tone={tone} pending={pending} />
        </>
    );
}

    tone: "idle" | "syncing" | "pending" | "offline" | "error". iconOnly esconde o label; labels sobrescreve os textos por tom.

    sync aceita o motor com o payload que ele tiver (OfflineSync<Nota> acima): a prop é tipada como SyncStatusSource, só o getState e o subscribe que o badge lê. Até a 0.92.0 ela era OfflineSync<unknown>, e todo motor tipado reprovava com TS2322 sob strict — o enqueue recebe o payload, então o motor não é covariante nele.

    StorageUsage

    Quando usar: mostrar quanto do armazenamento do navegador o app usa, quanto disso ainda não foi enviado ao servidor, e avisar quando o espaço está acabando ou quando os dados pendentes podem ser apagados pelo navegador. O componente não lê o navegador sozinho: recebe os números por prop. usage, quota e persisted vêm do useStorageEstimate; pendingBytes vem de quem sabe o que falta subir (o motor offline, a fila de upload do app); warnAt é o limite que o app escolhe.

    import { StorageUsage, useStorageEstimate } from "tempest-react-sdk";

export function Armazenamento({ pendingBytes }: { pendingBytes: number }) {
    const storage = useStorageEstimate({ pollMs: 30_000 });

    return (
        <StorageUsage
            usage={storage.usage}
            quota={storage.quota}
            persisted={storage.persisted}
            pendingBytes={pendingBytes}
            warnAt={0.9}
            onRequestPersist={storage.requestPersist}
        />
    );
}

    Mostra "X de Y usados · Z pendentes de envio" com os bytes formatados por formatBytes. Avisa em dois casos:

    • Acima do limite: usage / quota >= warnAt (default 0.8) pinta a barra de vermelho e mostra "Armazenamento quase cheio".
    • Pendências em armazenamento não permanente: persisted === false com pendingBytes > 0. Fora da tela inicial, o Safari apaga os dados do site depois de ~7 dias sem uso, e qualquer navegador pode despejar sob pressão de disco.

    Com persisted === false e onRequestPersist, aparece o botão "Tornar armazenamento permanente"; se o callback devolve uma promise, o botão fica em loading até ela terminar. O SDK não chama requestPersistentStorage() sozinho porque no Firefox isso abre um pedido de permissão: quem decide o momento é o app.

    Prop Tipo Default
    usage number \| null —
    quota number \| null —
    pendingBytes number \| null —
    persisted boolean \| null —
    warnAt number (razão em [0, 1]) 0.8
    onRequestPersist () => unknown —
    labels Partial<StorageUsageLabels> PT-BR

    null é "o navegador não informa": com usage ou quota null (ou quota 0) a barra dá lugar a uma frase, em vez de uma barra vazia que leria 0%. pendingBytes omitido esconde a linha de pendências; persisted null não mostra aviso nem botão.

    A11y: a barra é role="meter" (nível, não progresso de tarefa) nomeada pelo título, com aria-valuetext igual ao "X de Y usados" que o olho lê. Os avisos usam role="status" (polido), não o role="alert" padrão do Alert: o componente costuma montar numa tela com o aviso já verdadeiro, e um anúncio assertivo a cada montagem interromperia o leitor.

    PerfHud

    Seção perf da gallery — rode localmente para interagir.

    Quando usar: ver, em desenvolvimento, o que um createPerfMonitor está medindo — bateria e taxa de descarga, pressão de CPU, a latência do último toque e uma cascata das últimas interações com cada etapa. O componente não lê o navegador sozinho: recebe o snapshot do usePerfMonitor(monitor), então o mesmo monitor que alimenta a telemetria de produção alimenta o HUD.

    import { PerfHud, createPerfMonitor, usePerfMonitor } from "tempest-react-sdk";

const perf = createPerfMonitor();

export function DevOverlay() {
    const snapshot = usePerfMonitor(perf);
    return import.meta.env.DEV ? <PerfHud snapshot={snapshot} /> : null;
}

    Fechado, ocupa uma linha no canto ("Desempenho 82% · CPU normal · checkout 410 ms"); aberto, mostra:

    • Bateria: nível, "na bateria"/"carregando" e a taxa em %/h — ou "medindo consumo…" até o segundo degrau de 1 %.
    • CPU: o estado de pressão (normal, moderada, alta, crítica), em âmbar e vermelho nos dois últimos.
    • Último toque: barra empilhada de espera do input, handler e pintura, com o número de cada um.
    • Interações: as últimas maxReports, cada etapa numa linha recuada pela profundidade, com a barra posicionada pelo início e largura pela duração. Etapa que falhou fica vermelha.
    Prop Tipo Default
    snapshot PerfSnapshot —
    position "bottom-right" \| "bottom-left" \| "top-right" \| "top-left" \| "inline" "bottom-right"
    maxReports number 5
    defaultOpen boolean false
    labels Partial<PerfHudLabels> PT-BR

    Fonte que o navegador não expõe (bateria e pressão no Safari/Firefox) aparece como "indisponível neste navegador", nunca como zero; fonte suportada que ainda não respondeu aparece como "…". "inline" tira o position: fixed, para uma página de debug.

    A11y: é um <aside> nomeado pelo título — o único landmark; os blocos de dentro não são region, e um segundo HUD na mesma página recebe aria-label próprio — com o conteúdo dentro de um <details> nativo — abre e fecha pelo teclado sem script. As barras são decorativas (aria-hidden): cada uma tem o número escrito ao lado.

    UpdatePrompt

    Quando usar: avisar que há uma versão nova do app (service worker) e deixar o usuário recarregar. Par de useServiceWorkerUpdate.

    import { UpdatePrompt, useServiceWorkerUpdate } from "tempest-react-sdk";

export function AvisoDeAtualizacao() {
    const { updateAvailable, applyUpdate } = useServiceWorkerUpdate({ url: "/sw.js" });

    return <UpdatePrompt open={updateAvailable} onUpdate={applyUpdate} />;
}

    Renderiza nada com open={false}. onDismiss (opcional) mostra o botão de dispensar; position "top"/"bottom".

    A11y geral

    • Alert/Banner com variant warning/danger usam role="alert" (anunciado imediatamente).
    • Toast container é aria-live="polite" + aria-atomic="false" — só o toast novo é anunciado, não a pilha inteira. O ícone sem iconLabel fica aria-hidden.
    • Spinner/Progress.indeterminate adicionam aria-busy="true".
    • Skeleton é decorativo — não anuncia (aria-hidden).
    • Stat.value com tabular-nums alinha valores numéricos em colunas.

    Resumo

    • Nunca deixe uma ação assíncrona sem feedback: Spinner/Skeleton durante, Toast/Alert ao terminar.
    • Mensagens por escopo: Alert (inline/contextual), Banner (global/topo), Toast (transiente).
    • EmptyState = sucesso sem dados; ErrorState = falha com retry. Não troque um pelo outro.
    • Toast só para feedback descartável; erros acionáveis ficam em Alert/ErrorState.

    Páginas relacionadas:

    • Entrada de dados — error em campos de formulário, complementar a Alert de seção.
    • Dados — Table/DataTable que combinam com Skeleton (loading) e EmptyState/ErrorState.
    • Sobreposições — ConfirmDialog para ações destrutivas que pedem confirmação antes do Toast.
    • Layout — Grid para dispor vários Stat; Center para Spinner em tela cheia.
